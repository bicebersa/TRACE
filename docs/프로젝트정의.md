# TRACE 사업비 원인추적기 · 프로젝트 정의

- **정식 과제명:** 사업비 변동 원인분석 및 예산 점검 자동화
- **별칭:** TRACE (Trend 추이 · Risk 예산 위험 · Anomaly 이상치 · Cause 원인 · Expense 사업비)
- **환경:** 내부망·외부망 분리. 개발은 외부망에서 가상 데이터로 하고, 실행은 내부망의 Excel 2016 + VBA + HTML로 합니다. 실제 데이터는 외부로 나가지 않습니다. 반입 파일은 .xlsm(.xlsx) · .bas · .html · .css · .js뿐이며 설치가 필요 없습니다.

## 01 문제 정의

### 핵심 질문: 누가 어떤 상황에서 무엇을 어려워하나요?

예산·사업비 담당자는 매월 결산 후 사업비가 왜 늘었는지, 이 추세로 가면 예산이 언제 바닥나는지, 그것이 IFRS 17 손익과 CSM에 어떤 영향을 주는지를 판단해 보고해야 합니다. 경영진이나 감독원 등 대외기관이 물으면 근거도 제시해야 합니다.

- SAP 예산판은 부서·계정별 분기 실적, 배정, 조정, 잔여를 보여줍니다. 그러나 어떤 전표 때문에 늘었는지는 하나씩 클릭해야 알 수 있어서, 전체 원인을 빠르게 파악하기 어렵습니다.
- 예산판(부서 × 계정 × 분기), TB(계정 × 월), 전표(건별), BS·PL과 보험계약부채 변동표(감독원 양식)는 기준 단위가 서로 다릅니다. 그래서 전월·전분기·전년동기누적 비교를 하려면 손으로 다시 맞춰야 합니다.
- 예산 통제는 부서 × 계정 × 분기 한도인데, 남은 기간에 한도를 넘을지, 연간 예산이 언제 바닥날지는 담당자가 따로 계산해야 합니다.
- 어느 부서·계정부터 봐야 하는지는 담당자의 경험에 달려 있고, 원인을 확인하려면 부서에 묻고 답을 기다려야 합니다.
- IFRS 4·9 기준 사업비 전표가 계정대체(직접대체 → 투자부서 유지비의 재산관리비 대체 → 부서별 비율)를 거쳐 포트폴리오별 경험차이가 되고, 그것이 GMM·VFA는 CSM, 유지·수금비와 PAA는 당기손익으로 가는 경로를 한눈에 설명하기 어렵습니다.
- 망분리 환경이라 외부 분석 도구나 AI를 내부 데이터에 쓸 수 없습니다.

### 기대 변화: 어떤 상태로 달라지기를 바라나요?

- 예산판, TB, 전표, BS, PL, 예정사업비, 부채변동표 파일을 [불러오기] 버튼으로 넣으면, 사업비의 **전월 · 전분기 · 전년동기누적** 대비 변화가 부서·계정별로 자동으로 나옵니다. 실제 파일의 열 이름이 달라도 `헤더설정` 시트만 고치면 됩니다.
- 부서 × 계정 × 분기 한도로 **여유 / 주의 / 초과 예상 / 한도 초과 / 무예산**이 판정됩니다. 연간 예산은 월별 누계 실적에 맞춘 **직선(선형 추세)으로 고갈 예상일**을 계산합니다.
- 우선 확인할 부서·계정 **TOP 10**이 판단 근거 점수(증가액·증가율·이상치·예산)와 함께 나옵니다.
- 항목마다 "~때문일 것 같다"는 **원인 후보와 근거 전표**가 비교 기준별로 제시됩니다. 담당자는 전표를 찾는 대신 원인을 확인하고 결론을 내리는 데 집중합니다.
- 사업비가 **IFRS 17 CSM과 당기손익에 준 영향**(GMM·VFA·PAA)과 그 원인 전표가 함께 나오고, 계리 변동표(F31)와 대사됩니다.
- 결과는 엑셀 리포트와 **HTML 대시보드**(탭 5개, 엑셀 파일을 그대로 올려도 읽음)로 보고합니다.
- 확인된 원인은 코멘트로 쌓여 다음 달 분석과 대외 대응의 근거가 됩니다. 새로 알게 된 적요 표현을 키워드사전에 추가하면 원인 추정 정확도도 높아집니다.

## 02 검증 완료 기준

### 확인할 것: 어떤 가능성을 확인하려 하나요?

- **데이터 확보:** 예산판을 엑셀로 내보낼 수 있는지, 사업비 전표를 적요·거래처·코스트센터가 포함된 형태로 한꺼번에 추출할 수 있는지, 감독원 양식(BS·PL·부채변동표)과 계리 예정사업비를 받을 수 있는지
- **정합성:** 전표 합계, TB 합계, 예산판 실적 합계가 서로 맞아서 빠진 데이터 없이 분석할 수 있는지. 계정대체 전후 합계, 비귀속 = PL 기타사업비용, 재산관리비 대체액 = PL 재산관리비, 변동표 기말 = BS가 맞는지
- **판단 정확도:** 분기 한도 판정, 연간 고갈 예상, 주의 대상 선정이 담당자의 실제 판단과 맞는지
- **원인 추정 효용:** 규칙 기반 원인 후보 8가지(일회성 대형 지출, 신규 거래처, 단가 인상, 계상 시점 이동, 정정·역분개, 재분류, 적요 키워드, 물량 대 단가)가 실제 원인과 얼마나 맞고, 확인 시간을 얼마나 줄이는지
- **IFRS 17 연결:** TRACE가 추정한 포트폴리오별 신계약비 경험차이가 계리 변동표 F31과 얼마나 맞는지
- **운영 가능성:** 내부망 Excel 2016 + VBA에서 실제 데이터 규모로 쓸 만한 속도가 나오는지, 매크로 파일(.xlsm) 반입과 실행이 되는지

### 판단 근거: 어떤 결과면 검증을 마쳤다고 볼 수 있나요?

- 최근 [3]개월 데이터에서 전표 합계, TB 합계, 예산판 실적 합계의 차이가 0입니다. 차이가 나면 모두 원인을 설명할 수 있습니다. 자가진단 33항목이 '전체 정상'입니다.
- 전월·전분기·전년동기누적 비교 수치가 기존 수작업 결과와 100% 일치합니다.
- 과거 [2]개 분기를 다시 돌렸을 때, 실제로 한도를 넘은 부서·계정을 모두 '주의' 이상으로 미리 잡아냅니다.
- 연간 고갈 예상일이 실제 소진 월과 [1]개월 이내로 맞는 비율이 [70]% 이상입니다.
- 주의 대상 상위 [10]건 중 담당자가 "확인할 가치가 있었다"고 판단한 비율이 [70]% 이상입니다.
- 원인 후보가 실제 확인된 원인과 일치하거나 원인을 찾는 데 도움이 된 비율이 [60]% 이상입니다.
- TRACE 신계약비 경험차이와 계리 F31의 차이가 포트폴리오별 [5]% 이내이거나, 차이 원인을 설명할 수 있습니다.
- 월 분석·보고 시간이 [X시간]에서 [Y시간]으로 줄어듭니다.
- 전표 [N만 행] 기준으로 불러오기부터 분석 완료까지 [10]분 이내입니다.

## 범위와 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 1단계 | 전월·전분기·전년동기누적 비교, 분기 한도 판정, 주의 대상 TOP 10 (예산판 + TB + 전표) | 구현·가상 데이터 검증 완료 |
| 2단계 | 전표 기반 원인 추정 8패턴과 근거 전표 (비교 기준별) | 구현·검증 완료 |
| 3단계 | 리포트, 코멘트 누적, 키워드사전, HTML 대시보드, 헤더 이름 불러오기, 매크로 내장 .xlsm | 구현 완료, 내부망 실행 확인 필요 |
| 4단계 | IFRS 17 연결: 계정대체 규칙, 포트폴리오 경험차이, GMM·VFA CSM 브리지, PAA, 변동표 대사 | 구현·검증 완료 (실제 기준표 대기) |
| 5단계 | 예산 고갈 예상 (선형 추세, 연간·분기) | 구현, 수식 검증 진행 |
| 후속 | 상품·증권번호별 공통비 귀속 결과 반영, 월마감 이력 추세, 사업비 예실차(예상 대비 실제) 보고서 | 자료 수령 후 |

## 현재 진행 상황 (v0.5)

- **엑셀 본체:** 입력 7종(예산판·TB·전표·BS·PL·예정사업비·부채변동표), 헤더설정·입력옵션, 계정매핑·계정대체기준, 자가진단 33항목, 변동분석(분기 한도 · 연간 전망 · 선형 고갈 예상 · 누계 비교), 주의대상, 원인분석, IFRS17_사업비, 리포트, 엑셀 대시보드. Excel 2016 함수만 씁니다.
- **매크로:** 헤더 이름 기준 불러오기 7종, 감독원 가로 양식 합치기, 보조수식 채우기, 대시보드 내보내기(TOP 10 × 비교 기준 3개 원인분석), 리포트 PDF. 매크로가 들어간 `TRACE_v0.5.xlsm`은 열면 설정 시트에 버튼 10개가 생깁니다. 윈도우·맥 모두 한글이 깨지지 않게 만들었습니다.
- **HTML:** 대시보드(요약 · 사업비 · 주의 대상·원인 · IFRS 17 · 재무 요약), 처리 흐름, IFRS 17 연결도, 사용설명서, 내려받기. 외부 리소스 없이 오프라인으로 동작하고, data.js 또는 엑셀 파일을 그대로 올려 읽습니다.
- **검증:** 가상 데이터(예시보험㈜)로 엑셀 수식 전체를 계산해 별도 파이썬 계산과 대조했습니다. 수식 오류 0건, 대조 불일치 0건이며, 원인 패턴 시나리오 5건(일회성 대형, 재분류·역분개, 시점 이동, 단가 인상, 연간 키워드)이 의도한 원인으로 잡힙니다. 숫자를 바꾼 두 번째 예시(샘플생명㈜)도 함께 제공합니다.
- **다음 단계:** 내부망 반입·매크로 실행 테스트, 실제 SAP 예산판·전표와 감독원 양식에 헤더설정 맞추기, 관리회계 공통비 귀속 결과와 계리 예정사업비 단위 확인, 분기 한도 이월 여부 확인.
